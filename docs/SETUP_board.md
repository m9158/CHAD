# 게시판 설치 가이드

## 파일

| 파일 | 설명 |
|---|---|
| `db/schema_board.sql` | 테이블·RLS·트리거·뷰 전체 |
| `board.html` | 게시판 페이지 (기존 `styles.css` 재사용) |

---

## 1. DB 설정

Supabase 대시보드 → **SQL Editor** → `db/schema_board.sql` 전체 붙여넣기 → Run.
여러 번 실행해도 안전합니다.

## 2. Auth 설정

**Authentication → Providers → Email** 에서:

- `Enable Email provider` 켜기
- `Confirm email` — 초반 유입을 위해서는 **끄는 걸 권장**합니다. 켜두면 가입 후 메일 인증을 해야 로그인됩니다(HTML은 두 경우 모두 처리하도록 되어 있습니다).
- **Authentication → URL Configuration → Site URL** 에 `https://caucalendarcn.co.kr` 입력

## 3. 배포

`board.html` 을 `styles.css` 와 같은 위치에 업로드하고,
기존 `index.html` / `reviews.html` 의 `.tabs` 안에 탭 하나를 추가하세요.

```html
<a href="board.html" class="tab-link">广场 · 게시판</a>
```

## 구현된 것

- 로그인/회원가입 (이메일+비밀번호, 닉네임은 가입 시 메타데이터로 저장 → DB 트리거가 프로필 자동 생성)
- 글 목록 (20개씩 페이지네이션, 더보기)
- 글쓰기 / 삭제 (soft delete)
- 글별 익명 여부 선택 (에브리타임과 동일)
- 상세 보기 + 공감(♡) 토글
- 댓글 + 게시글별 익명 번호 자동 부여 (`匿名1`, `匿名2`, 글쓴이는 `楼主`)
- 신고 (5회 누적 시 자동 숨김), 중복 신고 차단

## 프라이버시 설계

`author_id` 는 클라이언트로 **절대 전송되지 않습니다.** 목록·상세는 `posts_public` /
`comments_public` 뷰만 조회하고, 뷰가 서버에서 `is_mine` 을 계산해서 내려줍니다.
author_id 를 그대로 내보내면 "익명 글 A와 익명 글 B가 같은 사람" 이라는 사실이
드러나 익명성이 무너지기 때문입니다.

공감 테이블도 본인 행만 조회 가능해서 "누가 눌렀는지" 목록은 나오지 않습니다.

또한 `like_count` · `report_count` · `is_hidden` 은 컬럼 단위로 UPDATE 권한을
막아두어 작성자 본인도 신고 수를 조작하거나 숨김을 해제할 수 없습니다.

## 아직 없는 것 (다음 단계 후보)

1. **스팸/도배 제한** — 지금은 마음만 먹으면 초당 수십 개 글을 쓸 수 있습니다.
   Postgres 트리거로 "최근 1분에 3개 이상이면 reject" 를 넣거나 Edge Function 사용.
2. **관리자 화면** — 신고 내역은 `service_role` 로만 조회됩니다. 당분간은 Supabase
   Table Editor 에서 직접 보면 되지만, 운영이 커지면 별도 페이지가 필요합니다.
3. **이미지 업로드** — Supabase Storage 연동 필요. 유해 이미지 대응 부담이 커지므로
   초기에는 넣지 않는 걸 권장합니다.
4. **알림** — 내 글에 댓글이 달렸을 때. 재방문을 만드는 가장 강한 기능이라 우선순위 높음.
5. **다중 게시판 분리** — `posts` 에 `board` 컬럼 하나 추가하면 됩니다. 글이 하루
   10개 이상 쌓이기 전에는 나누지 마세요.

## 법적 체크리스트 (익명 게시판 운영 시)

- 이용약관·개인정보처리방침 페이지 (수집 항목: 이메일, 닉네임)
- 게시물 신고·삭제 처리 절차 명시 → 정보통신망법상 임시조치 의무
- 교수 실명이 포함되는 강의평은 명예훼손 분쟁 소지가 있으므로, 사실 적시 중심으로
  작성하도록 안내 문구를 두는 편이 안전합니다.
