# CAU 中国留学生社区 (caucalendarcn)

중앙대학교 중국인 유학생을 위한 학사 정보 + 커뮤니티 서비스.

> **한 줄 요약** — 에브리타임은 한국어 네이티브 기준이라 중국인 유학생이 쓸 수 없다.
> 그 정보 격차를 학사일정 · 강의평 · 게시판으로 메운다.

- 배포 주소: <https://caucalendarcn.co.kr>
- 현재 버전: `v2.1` (학사일정 + 강의평) → `v3.0` 작업 중 (게시판 추가)

## 1. 현재 상태

| 기능 | 상태 | 비고 |
|---|---|---|
| 학사일정 캘린더 (`index`) | ✅ 배포됨 | 정적 데이터, `.ics` 다운로드 + 구글 캘린더 연동 |
| 강의평 게시판 (`reviews`) | ✅ 배포됨 | Supabase 연동, **로그인 없이 누구나 작성 가능** |
| 자유게시판 (`board`) | 🟡 코드 완성, 미배포 | 로그인 · 익명 · 댓글 · 공감 · 신고 |
| 회원 시스템 | 🟡 코드 완성, 미배포 | Supabase Auth (이메일 + 닉네임) |
| 도배/스팸 방지 | ❌ 없음 | **공개 전 필수** |
| 이용약관 · 개인정보처리방침 | ❌ 없음 | **회원 가입 받기 전 필수** |
| 관리자 화면 | ❌ 없음 | 당분간 Supabase Table Editor로 대체 |
| 알림 | ❌ 없음 | 재방문 유도의 핵심, Phase 1 |

### 알려진 문제

- **강의평이 무인증 공개 쓰기 상태다.** 게시판에 로그인을 붙이면 강의평만 무방비로 남는다.
  스팸 한 번이면 초기 인상이 무너지므로 게시판 배포와 동시에 강의평에도 로그인을 걸어야 한다.
- 페이지 3개가 헤더/네비게이션 코드를 각각 복사해서 갖고 있다. 탭을 하나 추가할 때마다
  모든 파일을 수정해야 한다.
- ~~파일명에 버전이 들어가 있다~~ → **2026-08 해결됨.** 다만 기존 `..._ver.1.1.html`
  주소로 공유된 링크가 전부 죽었다. `vercel.json` 에 리다이렉트를 넣어 살려야 한다.
- 저장소(`main`)와 실제 배포본이 다르다. 위 [파일 구조](#3-파일-구조) 주의 참고.

## 2. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | 순수 HTML + CSS + Vanilla JS | 빌드 도구 없음. 파일 올리면 끝. 팀 규모에 맞음 |
| 백엔드 | Supabase (Postgres + Auth + RLS) | 서버 코드 없이 DB · 인증 · 권한 해결 |
| 배포 | 정적 호스팅 | — |

**의도적으로 React/Next.js를 쓰지 않는다.** 지금 규모에서 프레임워크는 배포 난이도만
올린다. 페이지가 10개를 넘거나 상태 공유가 복잡해지면 그때 다시 논의한다.

## 4. 로컬에서 실행하기

**`file://` 로 HTML을 더블클릭하면 안 된다.** 두 가지 이유로 깨진다.

1. `styles.css` 같은 상대 경로 파일을 못 찾아서 스타일이 전부 빠진다
2. Supabase Auth가 `file://` 오리진을 거부한다

로컬 서버를 띄워야 한다.

```bash
# 저장소 루트에서
python3 -m http.server 5500
# → http://localhost:5500 접속
```

VS Code를 쓴다면 **Live Server** 확장으로도 된다.

GitHub를 처음 쓴다면 [`docs/GITHUB_GUIDE.md`](docs/GITHUB_GUIDE.md) 를 먼저 읽는다.
클론부터 PR까지 클릭 순서로 적혀 있다.

로컬 주소로 로그인까지 테스트하려면 Supabase 대시보드
**Authentication → URL Configuration → Redirect URLs** 에 `http://localhost:5500/**` 를 추가한다.

### UI만 빠르게 보고 싶을 때

`docs/board_preview.html` 은 CSS와 가짜 데이터가 파일 하나에 다 들어있어서
더블클릭만 해도 열린다. 서버·DB 없이 목록 → 상세 → 댓글 → 공감까지 눌러볼 수 있다.
단 상단 탭(학사일정/강의평)은 그 폴더에 파일이 없으므로 열리지 않는다. 정상이다.

## 5. DB 설정

1. Supabase 대시보드 → **SQL Editor** → `db/schema_board.sql` 전체 붙여넣고 Run
   (여러 번 실행해도 안전하게 작성되어 있다)
2. **Authentication → Providers → Email** 활성화
   - `Confirm email` — 초기 유입을 위해 **끄는 것을 권장**. 켜면 가입 후 메일 인증 전까지 로그인 불가
3. **Authentication → URL Configuration → Site URL** 에 `https://caucalendarcn.co.kr` 입력

`anon` (publishable) 키는 클라이언트에 노출되어도 되는 키다. 실제 접근 통제는 전부 RLS가 한다.
**`service_role` 키는 절대 프론트 코드에 넣지 않는다.**

## 6. 데이터 모델

```
auth.users ──1:1── profiles (nickname)
                      │
                      ├──< posts ──< comments
                      │       └──< post_likes
                      └──< reports
```

| 테이블 | 역할 |
|---|---|
| `profiles` | 닉네임. 가입 시 트리거가 자동 생성 (닉네임 중복 시 숫자 자동 부여) |
| `posts` | 게시글. `is_anonymous` 로 글마다 익명 여부 선택 |
| `comments` | 댓글. 게시글별 익명 번호를 트리거가 자동 부여 (`匿名1`, 글쓴이는 `楼主`) |
| `post_likes` | 공감. 본인 행만 조회 가능 → 누가 눌렀는지 노출되지 않음 |
| `reports` | 신고. 5회 누적 시 자동 숨김. 중복 신고 차단 |

### 익명성 설계 — 반드시 유지할 것

`author_id` 는 **클라이언트로 절대 내보내지 않는다.** 목록/상세는 `posts_public`,
`comments_public` 뷰만 조회하고, 뷰가 서버에서 `is_mine` 을 계산해 내려준다.

> author_id를 그대로 내려주면 "익명 글 A와 익명 글 B가 같은 사람"이라는 사실이 드러나
> 익명성이 무너진다. 익명 게시판에서 이건 치명적인 사고다.

`like_count` · `report_count` · `is_hidden` 은 컬럼 단위로 UPDATE 권한을 막아두어
작성자 본인도 신고 수를 조작하거나 숨김을 해제할 수 없다.

**새 쿼리를 추가할 때 `posts` / `comments` 테이블을 직접 select 하지 말 것.**
반드시 `_public` 뷰를 쓴다.

## 7. 개발 규칙

### 파일명에 버전을 붙이지 않는다

```
❌ index_ver.1.1.html   →   ✅ index.html
❌ board_ver.1.1.html   →   ✅ board.html
```

2026-08에 배포본은 정리했다. 다만 **옛 주소로 공유된 링크가 전부 죽었으므로**
`vercel.json` 에 리다이렉트를 넣어야 한다.

```json
{
  "redirects": [
    { "source": "/index_ver.1.1.html",   "destination": "/index.html",   "permanent": true },
    { "source": "/reviews_ver.1.1.html", "destination": "/reviews.html", "permanent": true }
  ]
}
```

버전 관리는 git이 한다. 릴리스는 태그로 남긴다.

```bash
git tag -a v3.0 -m "게시판 추가"
git push origin v3.0
```

파일명에 버전이 들어가면 파일 하나 올릴 때마다 다른 페이지의 링크가 전부 깨지고,
이미 공유된 링크가 죽고, 검색 엔진에 중복 페이지가 쌓인다.

### 브랜치

```
main            ← 배포되는 코드. 여기서 직접 작업하지 않는다
└── feat/board-notification
└── fix/review-auth
```

`feat/` `fix/` `docs/` 접두사 + 하이픈. PR로 합치고, 최소 1명 리뷰.

### 커밋 메시지

```
feat: 게시판 댓글 알림 추가
fix: 익명 번호가 중복 부여되는 문제 수정
docs: README에 DB 설정 절차 추가
```

### 코드 컨벤션

- 줄바꿈은 **LF**로 통일한다. `.gitattributes` 가 자동으로 처리하므로 신경 쓰지 않아도 된다.
  (이게 없으면 Windows에서 파일을 열기만 해도 전체가 "수정됨"으로 잡혀 diff를 볼 수 없게 된다)
- 사용자에게 보이는 문구는 **중국어 우선, 한국어 병기**. 한국어는 `.ko-sub` 클래스로 작게
- 색·간격은 `styles.css` 의 CSS 변수만 사용한다 (`var(--accent)`). 하드코딩된 hex 금지
- DB에서 온 값은 반드시 `esc()` 를 거쳐 DOM에 넣는다 (XSS 방지)

### Phase 1 — 재방문 만들기 (목표: 2~3주)

글이 쌓여도 사람이 다시 안 오면 죽는다. **이 단계가 서비스의 생사를 가른다.**

- [ ] **내 글에 댓글이 달리면 알림** — 재방문을 만드는 가장 강한 단일 기능. 최우선
  - 상단에 안 읽은 알림 뱃지 → 클릭 시 해당 글로 이동
  - `notifications` 테이블 + 댓글 INSERT 트리거
- [ ] 내가 쓴 글 / 댓글 / 공감한 글 모아보기
- [ ] 게시글 검색 (제목 + 본문, Postgres full-text search)
- [ ] 강의평 ↔ 게시판 상호 링크 (강의평 상세에서 "이 과목 이야기하기")
- [ ] 게시글 수정 기능

**완료 조건** — D7 재방문율 20% 이상.

### Phase 2 — 유입 (목표: 수강신청 4주 전부터)

**타이밍이 전부다.** 유학생 트래픽은 수강신청 직전 2주에 몰린다. 이 시점을 놓치면

- [ ] **공유 최적화** — 위챗/샤오홍슈에 링크를 붙였을 때 제목·설명·썸네일이 뜨도록
  `og:title`, `og:description`, `og:image` 추가. 위챗은 미리보기가 안 뜨면 클릭률이 급락한다
- [ ] 수강신청 D-day 배너 (학사일정 데이터 재활용)
- [ ] 신입생 가이드 콘텐츠 (외국인등록증, 통장 개설, 보험, 기숙사) — 검색 유입용
- [ ] 중국 본토 접속 가능 여부 실측 (VPN 없이). 막혀 있으면 유입 전략을 다시 짜야 한다
- [ ] 학과별 위챗 群에 배포 (선배·학생회 접촉)

**완료 조건** — 하루 신규 글 10개 이상.

### UI 관련

현재 UI는 "AI가 만든 랜딩페이지" 인상이 강하다. 원인은 대체로 정해져 있다.

| 문제 | 수정 방향 |
|---|---|
| 설명 문구가 많다 ("~하는 공간입니다") | 삭제. 실제 앱은 설명하지 않고 바로 콘텐츠를 보여준다 |
| 여백이 과하고 리스트 밀도가 낮다 | 한 화면에 글 8~10개가 보이도록 압축 |
| 이모지 사용 (🙌 ⚠ ♡) | SVG 아이콘으로 교체하거나 제거 |
| 폰트 크기 단계가 너무 많다 | 3단계로 축소 (제목 / 본문 / 메타) |
| 둥근 모서리 + 그림자 + 테두리 중복 | 구분선 하나로 통일 |
| 헤더가 두껍고 소개 영역이 크다 | 로고 + 탭만, 높이 절반으로 |

**어렵지 않다. 요소를 추가하는 게 아니라 빼는 작업이다.**
톤 방향(에브리타임식 고밀도 / 샤오홍슈식 / 현재 톤 유지)을 팀에서 먼저 합의하고 시작할 것.

## 10. 리스크 · 법적 체크리스트

### 익명 게시판 운영자의 의무

- **이용약관 · 개인정보처리방침 게시** — 이메일·닉네임을 수집하는 순간 필요하다
- **신고 · 삭제 처리 절차 명시** — 정보통신망법상 명예훼손 게시물에 대한 임시조치 의무가 있다.
  현재 신고 5회 자동 숨김이 구현되어 있으나, 신고 내역을 실제로 확인하는 사람이 있어야 한다
- **교수 실명 강의평** — 명예훼손 분쟁 소지가 가장 큰 영역이다. "사실 위주로 작성" 안내 문구 필수

### 서비스 리스크

| 리스크 | 대응 |
|---|---|
| **진짜 경쟁자는 에브리타임이 아니라 위챗 群이다** | 群에 없는 것 = 검색 가능한 축적 데이터(강의평·학사정보). 이걸 무기로 삼는다 |
| 콜드스타트 — 빈 게시판은 죽는다 | 유틸리티(학사일정·강의평)로 먼저 유입, 커뮤니티는 그 위에 얹는다 |
| 중국 본토에서 접속 차단 가능성 | Phase 2에서 실측 필요. 막히면 유입 경로를 한국 내 유학생 중심으로 재설계 |
| 초기 스팸 | Phase 0의 도배 방지 트리거 |
| 운영자 번아웃 | 신고 처리 담당자를 정해두고 돌아가며 맡는다 |

## 11. 성공 지표

숫자를 정해두지 않으면 "뭔가 하고는 있는데 되고 있는지 모르겠다"는 상태가 된다.

| 단계 | 지표 | 목표 |
|---|---|---|
| Phase 0 | 가입자 수 | 20명 |
| Phase 1 | D7 재방문율 | 20% |
| Phase 1 | 가입 → 첫 글 작성 전환율 | 30% |
| Phase 2 | 일 신규 글 | 10개 |
| Phase 2 | 수강신청 기간 DAU | 100명 |

Supabase SQL Editor에서 바로 확인할 수 있다.

```sql
-- 최근 7일 일별 신규 글
select date_trunc('day', created_at)::date as day, count(*)
from posts where created_at > now() - interval '7 days'
group by 1 order by 1 desc;

-- 가입 → 첫 글 전환율
select
  count(distinct p.id) as 전체_회원,
  count(distinct po.author_id) as 글쓴_회원,
  round(100.0 * count(distinct po.author_id) / nullif(count(distinct p.id), 0), 1) as 전환율
from profiles p left join posts po on po.author_id = p.id;
```
